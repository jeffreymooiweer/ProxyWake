# ProxyWake v4.3.0

## Summary

A reliability and usability release focused on the thing ProxyWake exists for: actually waking devices. Wake-on-LAN now sends the magic packet on every useful network path, the default Docker and Unraid setups use host networking so those packets reach your LAN, scheduled wakes get weekday selection and proper timezone support, and every guide has been rewritten in plain English for first-time users.

## Highlights

### Wake-on-LAN that reaches the device

Previously the magic packet was sent only to the device's IP address (unicast) unless you enabled the broadcast toggle. A sleeping machine no longer answers ARP, so unicast packets are often undeliverable. ProxyWake now sends to **all three** targets — unicast, subnet broadcast (or your custom broadcast address) and `255.255.255.255` — and a failure on one path no longer blocks the others. Broadcast is on by default for new devices, and the broadcast address can now be set in the edit dialog.

### Host networking by default

The number one reason for "nothing wakes" reports: Docker's default bridge network keeps broadcasts on a private network. The bundled `docker-compose.yml` and the Unraid Community Applications template now use **host networking**, and the docs explain why in plain terms. With host networking the web UI is on port **5001** of the host.

### Scheduled wakes: weekdays and timezone

The Automation tab lets you pick the days a schedule runs on, and the image now includes timezone data so `TZ=Europe/Amsterdam` makes "07:00" mean 07:00 where you live. The scheduler logs its active timezone at startup.

### Documentation rewritten

All guides were rewritten for people installing this for the first time, with corrected details (Home Assistant webhook integration, API paths, secret-key behaviour, rate limits) and a "wake does not work" checklist that walks through the real-world causes in order.

## Changed

- All generated integration snippets, log messages and audit entries are in English
- Non-JSON server errors are surfaced in the UI instead of being mistaken for success; wake progress toasts translate failure codes
- Audit log records the first `X-Forwarded-For` address
- Small backend cleanups: no duplicate dependency-chain wake in the public wake path, faster `/api/public/status`

## Upgrade notes

```bash
docker pull jeffersonmouze/proxywake:4.3.0
```

- **Switch to host networking** if you have not already (`--network host`, `network_mode: host`, or Network Type *Host* on Unraid). The UI then moves from your mapped port (e.g. `8462`) to `5001`. Update the ProxyWake URL in your proxy snippets accordingly.
- Set `TZ` if you use scheduled wakes.
- Existing devices keep their broadcast setting; turn **Broadcast WOL** on in the device settings for the new behaviour.
