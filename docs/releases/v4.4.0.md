# ProxyWake v4.4.0

## Summary

Wake-on-LAN now works from a **custom network** (macvlan/ipvlan, "Custom: br0" on Unraid) as well as from host networking, and the frontend has been moved from the retired Create React App toolchain to Vite with React 19 and MUI 9 — clearing all pending dependency updates without changing how the app looks or behaves.

## Highlights

### Wake-on-LAN from a custom network

Until now the guidance was "use host networking". You can also give ProxyWake its **own IP address on your LAN** with a macvlan or ipvlan network — on Unraid that is the *Custom: br0* network type with a fixed IP. ProxyWake now detects which of its interfaces is on the target device's LAN and sends the broadcast from there, so this works out of the box, also when the container is attached to the reverse proxy's bridge network at the same time. A new `docker-compose.macvlan.yml` shows the setup, and [Docker → Networking](../docker.md#networking-and-wake-on-lan) explains host vs. macvlan vs. bridge in plain terms. `PROXYWAKE_WOL_INTERFACE` pins the interface for unusual setups.

Plain bridge networks (Docker's default and `docker network create` bridges) still cannot carry Wake-on-LAN broadcasts — that is a Docker limitation, not a ProxyWake one. On a bridge network use the SSH, webhook, Home Assistant or IPMI wake methods.

### Frontend: Vite, React 19, MUI 9

Create React App (`react-scripts`) is no longer maintained and blocked every framework update. The frontend now builds with **Vite 8**, and runs **React 19.2**, **MUI 9.4**, **i18next 26** and **react-i18next 17**. The MUI `Grid` and `InputProps` APIs were migrated, and pages are loaded on demand so the first page load is about a third of the previous size. Every page, dialog and flow was re-verified in Chromium — 22 UI checks, zero errors. This supersedes Dependabot PRs #39, #48, #49, #50 and #51.

## Upgrade

```bash
docker pull jeffersonmouze/proxywake:4.4.0
```

No configuration changes are required. If you want ProxyWake on its own LAN IP, see `docker-compose.macvlan.yml` or switch the Unraid network type to *Custom: br0*; the web UI is then on port 5001 of that IP.

For contributors: the frontend dev server is now `npm run dev` (Vite) and the build requires Node 22.
